## Agreed bounded increment

The user authorized all recommendations from the repository review: evaluate an optional interaction boundary, implement one bounded graphical-linking feature, deliver preserved rc.32 and retain the human-review deferral. This increment adds the focused `/interaction` entry and `CategoryRange` directive; the compatibility root, core, supported existing inputs and all twelve existing payload caps remain unchanged. No general ECharts options, DataZoom, new engine registration, arbitrary links or disjoint selections are introduced.

An armed drag on the composed overview or on a device's horizontal monthly detail commits one inclusive supplied-order range to the same application-owned window. The application slices both charts, retaining full-history trend computation and raw point values. Native From/To, zoom/pan/reset and month actions remain. The new [API contract](../INTERACTION_API.md) defines cancellation, touch, focus and stale-context behavior.

The native rc.22-compatible dashboard source is preserved as a separately displayed/installed example, with the enhanced candidate source generated and checked separately. Both source variants correct select-option state during reordered data: a new browser test exposed that moving keyed option nodes could leave native From/To values stale despite the updated window. Explicit per-option selected bindings keep native fields aligned. The [initial browser failure](rc33/local/browser-initial.txt) remains recorded; corrected assertions are unchanged.

## Payload experiment

The first prototype preserves all existing scenario sizes but applies the single-family 200,000-byte gzip limit to the new combined composed+interaction scenario and fails at 201,742 bytes ([initial measurement](rc33/local/bundle-initial.txt)). This is an additional opt-in combination, not a change to the composed import. Existing caps are not raised. The new combination is measured against a separate incremental limit of 6,000 gzip / 8,000 Brotli bytes above the unchanged composed-only result; the isolated adapter has 110,000 / 95,000 total caps because its lazy getInstanceByDom dependency includes ECharts core but no chart family/Canvas registration. The combination must have exactly the composed-only engine module set and no eager engine code. Every original scenario must exclude the new entry.

The [rc.32 baseline](rc33/rc32-bundle-baseline.json) and [current results](rc33/local/bundle.txt) preserve actual measurements. Final measurements will be recorded after review. The bounded root/core margins remain a constraint on unrelated features; the optional boundary provides feature isolation rather than broad payload savings.
