## Contract and source

The [dashboard guide](../COMPOSED_DASHBOARD.md) defines application-owned month selection, raw segment actions, current-data detail derivation, independent legends, reset focus, missing/partial sums and supplied-order complete-window trend semantics. `/linked-dashboard` exposes stacked bar/area switching, immutable refresh/reorder/removal/empty/recovery controls and complete generated source. Its exact displayed `App` is compiled in an isolated npm rc.22 SSR consumer; source checks prevent example drift. The registry pilot deliberately remains pinned to immutable rc.22 while local library development advances.

The [horizontal API](../COMPOSED_CHART_API.md#horizontal-layout-in-local-rc23) adds `layout: 'vertical' | 'horizontal'` with vertical defaults and strict/runtime invalid-layout rejection. The category y-axis is inverse so supplied rows read top to bottom. Numeric formatting follows the value x-axis; bar signed end caps and area gradients rotate. Bar/area stack namespaces, raw observations, gap semantics, stable legends and renderer replacement behavior stay intact. Whole-line/area events use the active category coordinate; direct marker/bar IDs are unchanged. No new renderer registration, dependency or copied upstream source is added.

The regional fixture and target values are original illustrative data. Geometry follows the Apache ECharts [Cartesian-axis contract](https://echarts.apache.org/handbook/en/concepts/axis/) and existing [areaStyle contract](https://echarts.apache.org/handbook/en/how-to/chart-types/line/area-line/). Existing EvilCharts-derived fixture/palette and Apache notices remain required and byte-preserved.
